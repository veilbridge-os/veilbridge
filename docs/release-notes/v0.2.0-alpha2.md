> test on a router they can reach by cable. It is never offered as the latest
> release; the stable line is [v0.1.2](https://github.com/veilbridge-os/veilbridge/releases/tag/v0.1.2).
> `v0.2.0` ships when static routes and emergency access are done — track it
> on the [roadmap](https://github.com/orgs/veilbridge-os/projects/1) and the
> [v0.2.0 milestone](https://github.com/veilbridge-os/veilbridge/milestone/2).

## What is new

**Firewall screen** (menu: Network rules → Firewall). The first thing it says
is what is open from the internet, in one sentence. Below: port forwards, with
the device picked from the devices on your network; your own rules, numbered
in the order the router runs them, switched on and off, moved by dragging or
with arrows; the rules the firmware ships, folded and read-only; and the zones
as a reference. Every change goes through the same confirmation window as the
rest of the panel — if you lock yourself out, the router puts things back by
itself.

**Rules that would never act are refused.** On a firewall the first matching
rule wins, so a new rule placed below one that already decides the same
traffic would do nothing — and a panel that said "done" would be lying. Such a
rule is refused next to "Place in the list", with the name of the rule in the
way and a one-click "Put it before …". The same check guards moving a rule.
The router's own firewall also checks every draft before it is accepted.

**Settings search knows the usual words.** "port forwarding", "проброс
портов", "NAT" find the firewall, "DHCP" the local network, "PPPoE" the
internet connection — and the result says which word matched.

**Words router owners already know:** "DNS servers" instead of "Resolvers",
"MAC address" instead of "Hardware address", in both languages.

**Clearer warnings and diffs.** A warning about losing access now says how to
get back, with the address to open. Every staged change says which rule, port
forward or reserved address it is about. Lease time reads "12 hours → 2 hours".
A value the router refuses is shown next to the field it is about. The
countdown quotes the router's real confirmation window.

A device with one network port and no Wi-Fi has no local network to hand
addresses out on — the panel now says so and hides that section.

## Fixed since v0.2.0-alpha1

- A port forward being removed was listed, after reloading the page, as the
  bare word `redirect` instead of the forward itself — exactly when you were
  about to confirm it.
- An address reserved for a device could not be changed to another one: the
  router refused with "not a valid section name".
- A change to one of several rules or forwards did not say which one:
  switching off the rule that keeps the panel reachable read just "Rule is on:
  yes → no".
- The local network address was listed for confirmation with the words of the
  internet connection.
- On a 360 px phone the list of changes ran off the screen in Russian, and the
  "pin an address by hand" dialog was cut off.

## Not in this build

- Static routes and emergency access (a safe mode that resets only network
  changes) — the last two parts of `v0.2.0`.
- Firewall rules with conditions the panel does not show yet (source address,
  schedule, rate limit) are named, and can be switched on and off or removed,
  but not edited here.
- Switching an existing rule back on is not checked against the rules above
  it: if one of them already decides that traffic, the rule stays inert.
- Wi-Fi and the client list — keep LuCI for those.
- Built-in TLS: the panel speaks plain HTTP, so use it on a trusted network.
- Exit nodes and routing rules still use the screens from v0.1.

## Install, upgrade, go back

Keep a copy first: `cp -a /etc/veilbridge /root/veilbridge-backup`.

```sh
# try the pre-release (upgrades v0.1.x or alpha1, keeps /etc/veilbridge)
wget -qO- https://raw.githubusercontent.com/veilbridge-os/veilbridge/main/scripts/install.sh | VB_VERSION=v0.2.0-alpha2 sh

# go back to the stable line
wget -qO- https://raw.githubusercontent.com/veilbridge-os/veilbridge/main/scripts/install.sh | VB_VERSION=v0.1.2 VB_ALLOW_DOWNGRADE=1 sh
```

Running the plain installer (without `VB_VERSION`) on a router that has the
pre-release changes nothing: it refuses to go back to stable unless you set
`VB_ALLOW_DOWNGRADE=1`.

Package versions are `0.2.0~alpha2` (opkg) and `0.2.0_alpha2` (apk).

## Verified on

- **Risk gate** (`scripts/m1-rollback-e2e.sh`), both scenarios — revert by
  timeout and revert after the daemon is killed, then a working default route
  and a path to the internet — on an x86-64 OpenWrt 23.05.5 VM and on a Cudy
  WR3000S v1 (aarch64, OpenWrt 25.12.5), on the code of this release.
- **Firewall on the router, checked from outside**: a forwarded port opened
  inside the confirmation window, closed by itself when nobody confirmed,
  stayed open after confirming and closed when removed; a rule blocking the
  panel, put in front of the rule allowing it through the screen itself, cut
  the panel off and the settings came back by themselves. The firewall
  configuration was byte-identical afterwards.
