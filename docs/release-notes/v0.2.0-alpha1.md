## What is new

**Changes that cannot lock you out.** Network settings are no longer applied
the moment you press a button. A change is staged, shown as a before/after diff
in plain words, and applied inside a transaction: if your browser does not
confirm within the window, the router restores the previous settings by itself.
This holds even when the daemon dies in the middle — the revert then comes from
a journal on disk at the next start. It was proven by deliberately cutting the
router's own management link, on a VM and on a physical router.

**Internet screen.** Connection type (DHCP, static address, PPPoE), addresses
and DNS servers. If the panel stops answering during a change, it says so
instead of waiting silently, and a failed revert never leaves you without a way
to apply again.

**Local network screen.** Router address, the range of addresses handed out,
lease time, the devices holding an address right now, and reserving an address
for a device straight from that list.

**A rebuilt panel.** New shell and dashboard: model, firmware, load, memory and
the writable space that actually runs out first, updated live over one stream
instead of polling, with a short history kept in RAM (nothing is written to
flash). Sections the hardware cannot support are hidden, with the reason. Dark
theme, layouts from 360 px.

**Engine chosen by the device.** The tunnel uses kernel TUN where the router has
it and a userspace fallback where it does not; the choice is reported by the API.

## Not in this build

- Firewall and port forwarding, static routes, Wi-Fi, the client list — keep
  LuCI for those.
- Built-in TLS: the panel speaks plain HTTP, so use it on a trusted network.
- Exit nodes and routing rules use the screens from v0.1; they are redesigned
  with exit policies in `v0.3.0`.
- A few labels still use code words ("Resolvers" instead of "DNS servers") —
  [#26](https://github.com/veilbridge-os/veilbridge/issues/26).

## Install, upgrade, go back

Keep a copy first: `cp -a /etc/veilbridge /root/veilbridge-backup`.

```sh
# try the pre-release (upgrades an existing install, keeps /etc/veilbridge)
wget -qO- https://raw.githubusercontent.com/veilbridge-os/veilbridge/main/scripts/install.sh | VB_VERSION=v0.2.0-alpha1 sh

# go back to the stable line
wget -qO- https://raw.githubusercontent.com/veilbridge-os/veilbridge/main/scripts/install.sh | VB_VERSION=v0.1.2 VB_ALLOW_DOWNGRADE=1 sh
```

Package versions are `0.2.0~alpha1` (opkg) and `0.2.0_alpha1` (apk); both
package managers order them after `0.1.x` and before `0.2.0`. The daemon binary
is ~2.4 MB larger than in v0.1 because the userspace fallback engine ships on
every device.

## Verified on

- **Risk gate** (`scripts/m1-rollback-e2e.sh`), both scenarios — revert by
  timeout and revert after the daemon is killed — on an x86-64 OpenWrt 23.05.5
  VM and on a Cudy WR3000S v1 (aarch64, OpenWrt 25.12.5), on the code of this
  release.
- **Upgrade rehearsal** with packages built by the release recipe: 0.1.1 →
  0.2.0~alpha1 with opkg and 0.1.8 → 0.2.0_alpha1 with apk, configuration kept,
  service running, sign-in working; and back to v0.1.1 with opkg.
