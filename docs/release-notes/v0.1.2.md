A packaging fix on the `v0.1` line. **The daemon and the panel are the same as
in v0.1.1**; only how VeilBridge gets onto a router changed.

## Fixed

- **OpenWrt 25.12 and later can install VeilBridge.** 25.12 replaced opkg with
  apk, and v0.1.1 shipped only `.ipk`, so the one-line installer failed there
  with "download failed". This release ships `.apk` next to `.ipk`, and the
  installer picks the format the router can use.
- **A package for the wrong CPU no longer kills a working installation.** Under
  opkg the package is refused before anything is unpacked, and the running
  panel is left alone. apk cannot refuse (it ignores the result of package
  scripts), so there the working binary is saved before the overwrite and put
  back afterwards.

## Install or upgrade

On the router:

```sh
wget -qO- https://raw.githubusercontent.com/veilbridge-os/veilbridge/main/scripts/install.sh | sh
```

Upgrading keeps `/etc/veilbridge` (nodes, settings, password). The installer
now checks that the binary it installed is exactly the one from the release.

## Verified on

A Cudy WR3000S v1 (aarch64) on OpenWrt 24.10.8 with opkg and 25.12.5 with apk,
and an x86-64 OpenWrt 23.05.5 VM: clean install, upgrade with the config kept,
removal that keeps the keys, start after reboot, and a wrong-CPU package on both
package managers.
