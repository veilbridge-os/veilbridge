> **Pre-release.** `v0.2.0-beta1` with one serious fix for its firewall writes, for people testing on a router they can reach by cable. Nothing new. It is never offered as the latest release; the stable line is [v0.1.2](https://github.com/veilbridge-os/veilbridge/releases/tag/v0.1.2). The API of `v0.2.0` stays frozen. Built from the `release/v0.2` branch: `main` has already moved on to `v0.3`.

## Read this first: upgrade from beta1

In `v0.2.0-beta1` the router's own firewall never checked a port forward or a traffic rule before it was staged ([#61](https://github.com/veilbridge-os/veilbridge/issues/61)). The panel was not allowed to start the check, took that failure for "no warnings", and staged every draft. An entry the firewall then skips could be applied and confirmed, and the panel called it done. If you added port forwards or rules with beta1, open them in LuCI once: an entry the firewall skips is marked there.

Everything else in the [beta1 notes](https://github.com/veilbridge-os/veilbridge/releases/tag/v0.2.0-beta1) still applies, starting with **routing rules do not route yet** (#47).

## Fixed since v0.2.0-beta1

- **The firewall check runs** before a port forward, a traffic rule or a move of a rule is staged. A draft the router's firewall would drop is refused at once, with the firewall's own words. The firewall's notes that do not drop anything are not refusals: "disabling reflection" on a plain port forward (OpenWrt 23.05), and an entry staged switched off. If the check itself cannot run, nothing is staged, and the panel says why.
- English counts of zero read "0 address" and "0 minute ago". They now read "0 addresses" and "0 minutes ago".

## Not in this build

As in beta1. Routing rules do not route (#47). IPv6 static routes are listed but not edited. Firewall rules with conditions the panel does not show yet can be switched on and off or removed, but not edited. Failsafe for the emergency command is proven on a VM only. For Wi-Fi and the client list, keep LuCI. The panel has no built-in TLS.

## Install, upgrade, go back

Keep a copy first: `cp -a /etc/veilbridge /root/veilbridge-backup`.

```sh
# try the pre-release (upgrades beta1, the alphas and v0.1.x, keeps /etc/veilbridge)
wget -qO- https://raw.githubusercontent.com/veilbridge-os/veilbridge/main/scripts/install.sh | VB_VERSION=v0.2.0-beta2 sh

# go back to the stable line
wget -qO- https://raw.githubusercontent.com/veilbridge-os/veilbridge/main/scripts/install.sh | VB_VERSION=v0.1.2 VB_ALLOW_DOWNGRADE=1 sh
```

Running the plain installer (without `VB_VERSION`) on a router that has the pre-release changes nothing: it refuses to go back to stable unless you set `VB_ALLOW_DOWNGRADE=1`.

Package versions are `0.2.0~beta2` (opkg) and `0.2.0_beta2` (apk).

## Verified on

- **Risk gate** (`scripts/m1-rollback-e2e.sh`). Both scenarios passed on the device code of this release: revert by timeout, and revert after the daemon is killed, followed by a working default route and a path to the internet. Stands: an x86-64 OpenWrt 23.05.5 VM and a Cudy WR3000S v1 (aarch64, OpenWrt 25.12.5).
- **The firewall check, with the real firewall on both.**
  - A port forward stages, both on and switched off, while `fw4` prints its notes.
  - On the router, a draft that the firewall reported as skipped (the report was injected) was refused with the firewall's line, and nothing was left staged.
