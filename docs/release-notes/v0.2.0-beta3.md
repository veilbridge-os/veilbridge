> **Pre-release.** `v0.2.0-beta2` with one packaging fix: a firmware upgrade that keeps settings now keeps the panel's data too. Nothing new, the daemon is the same code as beta2. It is never offered as the latest release; the stable line is [v0.1.2](https://github.com/veilbridge-os/veilbridge/releases/tag/v0.1.2). The API of `v0.2.0` stays frozen. Built from the `release/v0.2` branch: `main` has already moved on to `v0.3`.

## Read this first: install beta3 before you flash

Up to beta2 the package never told OpenWrt about `/etc/veilbridge`, where the panel keeps its admin password hash, VPN keys and restore points ([#62](https://github.com/veilbridge-os/veilbridge/issues/62)). A firmware upgrade that keeps settings dropped all of it, and the standard backup did not contain it.

- Only a package that already has the fix protects the data. **Upgrade to beta3 first, then flash.**
- The firmware does not bring the package back: install it again after flashing, and it picks up the kept settings.
- The standard OpenWrt backup now contains the panel's password hash and VPN private keys. Keep it as private as the keys themselves.
- A change still waiting for confirmation when you flash comes back with its snapshot, so the panel on the new firmware undoes it, exactly as after a reboot in the confirmation window. Confirm or cancel changes before flashing.

Everything else in the [beta2 notes](https://github.com/veilbridge-os/veilbridge/releases/tag/v0.2.0-beta2) and the [beta1 notes](https://github.com/veilbridge-os/veilbridge/releases/tag/v0.2.0-beta1) still applies, starting with **routing rules do not route yet** (#47).

## Fixed since v0.2.0-beta2

- **A firmware upgrade that keeps settings keeps the panel's data.** The package ships `/lib/upgrade/keep.d/veilbridge`, which adds the whole of `/etc/veilbridge` to what sysupgrade keeps: the settings, VPN keys, restore points and a change waiting for confirmation. The release check now fails if either package lacks it.

## Not in this build

As in beta2. Routing rules do not route (#47). IPv6 static routes are listed but not edited. Firewall rules with conditions the panel does not show yet can be switched on and off or removed, but not edited. Failsafe for the emergency command is proven on a VM only. For Wi-Fi and the client list, keep LuCI. The panel has no built-in TLS.

## Install, upgrade, go back

Keep a copy first: `cp -a /etc/veilbridge /root/veilbridge-backup`.

```sh
# try the pre-release (upgrades beta2, beta1, the alphas and v0.1.x, keeps /etc/veilbridge)
wget -qO- https://raw.githubusercontent.com/veilbridge-os/veilbridge/main/scripts/install.sh | VB_VERSION=v0.2.0-beta3 sh

# go back to the stable line
wget -qO- https://raw.githubusercontent.com/veilbridge-os/veilbridge/main/scripts/install.sh | VB_VERSION=v0.1.2 VB_ALLOW_DOWNGRADE=1 sh
```

Running the plain installer (without `VB_VERSION`) on a router that has the pre-release changes nothing: it refuses to go back to stable unless you set `VB_ALLOW_DOWNGRADE=1`. Going back to v0.1.2 also removes the keep.d entry, so the data is no longer kept by firmware upgrades.

Package versions are `0.2.0~beta3` (opkg) and `0.2.0_beta3` (apk).

## Verified on

- **The daemon is unchanged since beta2** (no Go code changed on `release/v0.2`), so the beta2 risk gate and firewall checks still describe it. The checks that CI runs on `main` were run by hand on this commit: formatting, vet, tests, the OpenAPI snapshot, lint and the web build.
- **OpenWrt 23.05.5 / opkg, x86-64 VM:** a full keep-settings firmware upgrade with the fixed package. The config and all five restore points came back byte for byte with mode 0600; after reinstalling the package the old admin password logged in, a wrong one was refused, and emergency restore listed every restore point.
- **OpenWrt 25.12.5 / apk, Xiaomi AX3000T:** with the fixed package, `sysupgrade -l` lists `/etc/veilbridge/config.json`, and a real `sysupgrade -b` archive contains it with mode 0600 and identical content. No firmware was flashed on that router for this check.
